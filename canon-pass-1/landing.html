01 / возможности

Не набор скриптов.
Напарник с характером.

Шесть систем, которые работают как один организм: сенсорика, память, PII-обработка и офлайн-фолбэк — локально; облачный LLM-контур подключается отдельно.

Полнодуплексный голос с barge-in

Говори поверх — он уступит слово за доли секунды и продолжит с учётом сказанного. VAD на ONNX, распознавание Whisper, синтез Piper. Сырой аудиобайт не покидает машину; облачный LLM-контур — по опции.

Архи…поэтому я бы вынес парсинг в отдельный модуль, так тесты лягут проще—

Z-Sense: видит твой экран

Локальный OCR читает активное окно, а базовая PII-обработка готовит текстовый контекст. Никакого «скопируй сюда текст» — он уже посмотрел и понял, чем ты занят.

Приватность: edge-first

Локальный контур — основа: сенсорика, память и офлайн-фолбэк работают на устройстве. Облачный LLM подключается отдельно по конфигурации.

  • Модели на диске: Whisper, Piper, локальный LLM
  • Память — в SQLite у тебя, не в чужой базе
  • Облако — только при включённой конфигурации и opt-in
  • Экспорт и полное удаление одной командой

05 / запуск

Твой экран. Твой голос.
Твои данные.

Память как у человека. Дисциплина как у машины. Разворачивается одной командой: локальные сенсоры, память и офлайн-фолбэк остаются у тебя, а облачный LLM-контур подключается отдельно.

$./dev.sh

edge-first · без аккаунта · cloud LLM — по opt-in/конфигурации · telemetry в MVP не реализована

Текущий MVP — локальный контур

  • VAD, STT, TTS, память — локально (архитектура edge)
  • Облачный LLM-контур — opt-in/конфигурация
  • PII-обработка — базовый sanitizer в MVP
  • Сырой экран/аудио — предназначены оставаться на устройстве
  • Облачные вызовы — только при включённом cloud контуре
  • Передачи данных — санированным текстом; egress-контроли нужно проверить
  • Telemetry — не реализована в MVP; crash upload/analytics — планируются с opt-in
DEVICECLOUD · opt-in

Граница данных: сырые кадры экрана и аудио предназначены оставаться на устройстве. Через cloud boundary допускается только санированный текстовый контекст — при включённых и проверенных sanitizer/egress-контролях; текущий MVP содержит базовый sanitizer.

Четыре независимых границы

Каждый consent-тумблер управляет своей зоной. Границы независимы, работают параллельно и всегда закрыты, пока пользователь сам их не откроет — ни одна из них не включается по умолчанию.
